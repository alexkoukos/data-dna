# Οδηγός ομάδας: πώς δουλεύουμε όλοι στο ίδιο repo

Ο στόχος: όποιος κι αν πιάσει τη δουλειά (π.χ. επειδή τελείωσαν τα tokens του προηγούμενου), συνεχίζει σε 5 λεπτά, με ίδιο περιβάλλον και τα ίδια tests.

## 1. Στήσιμο μία φορά (Windows)

1. **WSL:** PowerShell ως διαχειριστής → `wsl --install` → επανεκκίνηση → ορίζετε username και password στο Ubuntu.
2. **RAM για το WSL:** φτιάξτε το `C:\Users\<όνομα>\.wslconfig` με:
   ```
   [wsl2]
   memory=8GB
   ```
   και τρέξτε `wsl --shutdown`.
3. **Docker Desktop:** εγκατάσταση, μετά Settings → General → «Use the WSL 2 based engine» και Settings → Resources → WSL integration → ενεργοποίηση για Ubuntu.
4. **VS Code:** εγκατάσταση, μετά τα extensions «WSL» και «Dev Containers».
5. **Git μέσα στο Ubuntu:** ανοίξτε Ubuntu και τρέξτε:
   ```
   git config --global user.name "Το Όνομά σας"
   git config --global user.email "το-email-σας"
   ```
6. **Πρόσβαση στο repo:** ο Αλέξανδρος σας προσθέτει στο GitHub. Αποδεχτείτε την πρόσκληση από το email.
7. **Clone μέσα στο WSL (όχι στο C:\\):**
   ```
   cd ~
   git clone <το link του repo>
   cd data-dna
   code .
   ```
8. Στο VS Code πατήστε **«Reopen in Container»** όταν το προτείνει. Την πρώτη φορά αργεί λίγα λεπτά: στήνει Python, Node, Docker, Claude Code και όλα τα dependencies **ακριβώς ίδια** με των υπολοίπων.
9. Μέσα στο VS Code: ανοίξτε το Claude Code (εικονίδιο στα δεξιά) και κάντε Sign in.

Χωρίς Dev Container: μέσα στο Ubuntu τρέξτε `make doctor`, εγκαταστήστε ό,τι λείπει, και μετά `make setup`.

## 2. Η καθημερινή ροή (3 εντολές)

Στο Claude Code γράφετε:

| Εντολή | Τι κάνει |
| --- | --- |
| `/start Βασίλης` | Φέρνει τις αλλαγές των άλλων, διαβάζει πού σταμάτησε ο προηγούμενος, σας λέει τι ακολουθεί |
| `/task T3` | Αναλαμβάνει μια δουλειά από το `TASKS.md` και τη δουλεύει μαζί σας |
| `/handoff` | Σώζει τα πάντα: σημείωμα στο `PROGRESS.md`, commit, push, και σας δίνει link να το στείλετε στην ομάδα |

Για δεδομένα, χωρίς κώδικα: `/add-data prompts`, `/add-data tools` ή `/add-data org`. Του περιγράφετε τι θέλετε στα ελληνικά, γράφει αυτό τα αρχεία, και τα ελέγχει με `make validate`.

## 3. Όταν τελειώνουν τα tokens

1. Πριν τελειώσουν εντελώς, γράψτε **`/handoff`**.
2. Στείλτε στο group το link του PR που σας δίνει.
3. Ο επόμενος ανοίγει το repo, γράφει `/start <όνομα>` και συνεχίζει ακριβώς από εκεί.

Αν κόπηκε απότομα χωρίς handoff: ο επόμενος γράφει «Ο προηγούμενος σταμάτησε απότομα στο branch X, δες τι έχει αλλάξει με git diff και γράψε handoff entry πριν συνεχίσουμε».

## 4. Κανόνες που δεν σπάμε

- Ποτέ αλλαγές απευθείας στο `main`. Πάντα branch και PR (το Claude Code το κάνει μόνο του).
- Πριν από κάθε commit: `make check` (το κάνει επίσης μόνο του). Αν κάτι είναι κόκκινο, δεν το σπρώχνουμε.
- Κανένα πραγματικό πρόσωπο, αριθμός ή εταιρεία στα δεδομένα. Όλα φανταστικά.
- Κανένα κλειδί (API key) σε αρχεία εκτός από το `.env`, που δεν ανεβαίνει ποτέ.
- Ένα PR το κάνει merge κάποιος άλλος από αυτόν που το έγραψε, αφού το CI είναι πράσινο. Για τα αρχεία δεδομένων αρκεί πράσινο CI.

## 5. Πού είναι τι

| Αρχείο | Τι έχει |
| --- | --- |
| `docs/IDEA_AND_TEAM.md` | Η ιδέα, οι ρόλοι, τα παραδοτέα του ΔΕΤ |
| `docs/PRD.md` | Το τεχνικό σχέδιο |
| `TASKS.md` | Ποιος κάνει τι, τι έμεινε |
| `PROGRESS.md` | Πού σταμάτησε ο καθένας (το πιο πρόσφατο πάνω) |
| `CLAUDE.md` | Οι κανόνες που ακολουθεί το Claude Code |
| `data/` | Τα δεδομένα της ομάδας: prompts, AI εργαλεία, οργανισμός, έγγραφα |
| `docs/business/` | Έρευνα, SWOT, τιμή, roadmap, GDPR |

| `make up` | Ξεκινάει όλο το σύστημα. App: http://localhost:3000 |
| `make down` | Το σταματάει |
| `make check` | Όλοι οι έλεγχοι |
| `make validate` | Ελέγχει μόνο τα αρχεία δεδομένων |
